# Transformation Hub — Operator Runbook (SOP)

> The operational SOP for running and maintaining the Hub
> (`hub.agroecologyindia.org`). Optimized for **"can someone else run this if the
> primary maintainer is out"** — the repo is public and re-deployable, so this
> focuses on the handful of operations that actually carry risk.
>
> Companion: **[Admin User Manual](./sop-admin-manual.md)** (how to update content).
> Action item from the **CAT Tracker Discussion (24 Jun 2026)**.

## 0. The golden rules (read first)

1. **Deploy ONLY via `git push origin main`.** Vercel auto-deploys. **Never** run
   `vercel deploy` / the Vercel CLI — it bypasses the pipeline.
2. **Never destructively re-ingest a *published* landscape** without the canonical
   source file in hand. DB rows are **not recoverable**.
3. **"Publish" means the full pipeline**, not flipping a flag (see §3).
4. **The Ask assistant reads only the library, never the open web.** Only the admin
   factsheet generator (Gemini) touches the web.

## 2. Deploy

1. Commit to a branch, open a PR (or commit to `main` if trusted).
2. `git push origin main` → Vercel builds and deploys automatically.
3. Verify the live marker (a changed string or the page itself) once the build
   completes. If two pushes land close together and Vercel skips the newer build,
   push an **empty commit** to force a fresh deploy:
   `git commit --allow-empty -m "redeploy" && git push`.
4. **Never** use the Vercel CLI to deploy.

---

## 3. Publish a landscape (highest-risk recurring op)

"Publish" = the **whole pipeline**, in this order:

1. **Ingest** the LIP report + budget workbook:
   `node scripts/ingest-landscape.mjs <slug> <docx> <xlsx>`
   (This writes narrative + budget chunks + `landscape_budget_lines`.)
2. **Wait** for the ingest to fully finish — a big ingest can outlast a build.
3. **Flip status in code:** set `lipStatus: "published"` for the landscape in
   `lib/data/landscapes.ts`. (Status is **code-driven**, not a DB column.)
4. **Reproject page content into RAG:** `npx tsx scripts/ingest-page-profile.ts <slug>`
   — re-run after any `lib/data` edit so Ask answers from the live page content.
5. **Push** (`git push origin main`) and verify the landscape shows as published with
   its budget lines present. If budget shows "0 lines", the ingest finished after the
   build — push an empty commit to redeploy.

> ⚠️ **Before any re-ingest of an already-published landscape, confirm you have the
> canonical source files.** Canonical Patratu = `-patratuyupload 5.2.xlsx` +
> `uploadsPatratu_LIP_3plus4_FINAL_1.docx`. No canonical file → do not re-ingest.

---

## 4. Solutions Atlas / factsheets

- Fact sheets are generated by an **admin batch** (OpenRouter / Gemini Flash, web-
  grounded). This is the **only** path that fetches from the open web.
- Generated fact sheets are embedded into `factsheet_chunks` and become both Atlas
  pins and Ask sources automatically.
- Visitor questions never trigger web fetches — they hit the free NVIDIA library path.

## 5. Maintenance / O&M

| Task | How / cadence |
|---|---|
| Rotate secrets | On any ownership change or suspected exposure. Vault-stored. |
| Monitor uptime | Vercel dashboard; check after each deploy |
| DB health | Neon dashboard — storage vs the 500 MB free limit; upgrade if approaching |
| Dependency updates | Periodic; test on a branch, verify a preview deploy before merge |
| Re-index after content edits | Re-run `ingest-page-profile.ts` after editing `lib/data` |
| Backups | Neon point-in-time recovery; the public repo is the code backup |

---

## 6. Disaster recovery (if an account is lost)

Because the repo is **public** and re-deployable:

1. Re-import the repo into a company Vercel project.
2. Stand up a fresh Neon DB; restore from the latest Neon backup **if available**.
3. If no DB backup, **re-ingest only from canonical source files** (never improvise
   published-landscape data).
4. Re-enter rotated secrets; re-point DNS if needed; verify Ask + a landscape page.
